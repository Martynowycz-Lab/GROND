# Troubleshooting

If `GROND doctor --probe-bloch --strict` fails, the Python environment is not ready. Reinstall the package in a clean Python 3.11 to 3.13 environment and check that NumPy, SciPy, and Gemmi import correctly. Python 3.12 remains the easiest default on most laptops and shared servers. Plain `GROND doctor` remains a report-only command for scripts that need to inspect an incomplete environment without a nonzero exit.

If the run stops during preflight, inspect `decisions/<dataset>/preflight.json`. Common causes are missing numeric reflection rows, too few positive intensities, non-positive sigmas, or geometry columns that are absent or badly tailed.

If endpoint statistics or maps are missing, check whether external crystallographic programs are on `PATH`. GROND can still run native row-level modeling without those tools, but merged endpoint statistics and maps require external programs.

If `GROND auto` stops with an SFAC message, run `GROND sfac-check --structure model.res`. Element-only SHELX lines such as `SFAC C H N O` are not a valid GROND Bloch model because they rely on SHELXL's built-in scattering table. Replace them with explicit electron scattering coefficient rows, then rerun. The check also warns when the `CELL` wavelength is a placeholder or X-ray value; GROND endpoint `.ins` files use `0.025079 A` in those cases.

GROND currently writes corrected small-molecule endpoints as `HKLF 4` intensity files. If the starting SHELX model contains `ACTA`, GROND strips it from generated endpoint inputs because it can interfere with zero-cycle/check runs and is not needed for corrected-HKL refinement. If the starting model contains `HKLF 3`, GROND can still use the model but generated endpoints are forced to `HKLF 4`. `HKLF 5`, `TWIN`, `BASF`, `SWAT`, and SQUEEZE/solvent-mask corrected SHELX models are current limitations and are rejected before the long run starts.

If `GROND auto` stops immediately with a missing-tool message, run `GROND init-config --out grond.config.json`, fill in absolute paths for `shelxl` and `shelx2map`, and rerun with `--config grond.config.json`. `GROND doctor --config grond.config.json --probe-bloch` prints the resolved executable path, whether it came from config, environment, or `PATH`, and what aliases were checked. For a deliberate row-only run, add `--native-only`; for endpoint statistics without maps, add `--no-maps`; for incomplete diagnostics only, add `--allow-missing-tools`.

If DIALS import fails with an error about `dials` or `dxtbx`, pass the DIALS Python executable explicitly with `--dials-python /path/to/dials/python`. GROND itself can live in a separate supported Python environment; the import bridge launches the DIALS Python only to read `.refl` and `.expt` files.

If DIALS import stops at the geometry gate, inspect `dials_bridge_summary.json` in the requested bridge directory. The bridge preserves DIALS' raw z coordinates, records both image and array ranges, and uses the array-range start as `STARTING_FRAME`; cropped scans therefore require no manual frame renumbering. GROND refuses to write a new `INTEGRATE.HKL` when the 95th percentile of `|Sg|` exceeds `0.005 A^-1`. A failure normally means the `.refl` and `.expt` do not belong together, the scan-varying crystal model was not preserved, or the input uses unsupported geometry. Correct the input pairing or geometry instead of widening the downstream local-root search.

If DIALS gives reasonable R1 values but much worse weighted residuals than an XDS reduction of the same frames, inspect the `sigma_model` block in `dials_bridge_summary.json`. For DIALS rotation data, put the gain on the detector model at import time with `panel.gain=<gain>` rather than relying on `integration.summation.detector_gain`. GROND's default `raw` mode preserves the DIALS variance. `--dials-sigma-mode detector_gain` forces a `sqrt(gain)` multiplier, while `--dials-sigma-mode auto` fits an empirical duplicate-scatter model; both are diagnostics. If `dials_bridge_summary.json` shows the median `I/sigma` collapsing by roughly `sqrt(gain)`, the gain was probably applied twice and the run should be repeated with raw sigmas. Also check whether many rows were dropped by `dont_integrate` or bad-pixel flags, because failed background modelling can otherwise look like unrealistically precise weak data.

If `wR2all` looks much worse than `R1all`, first check the endpoint `post_bloch_sigma` block, `wght_mode`, and `iteration_history` in `summary.json` or the endpoint `.lst` files. Full auto should show final publication endpoints and SHELXL feedback cycles using `post_bloch_sigma.policy=uniform_z_rms` unless the policy was forced off, and the production endpoint should normally show active `WGHT 0 0`. Inherited or promoted SHELXL empirical weights are diagnostic branches. A first-cycle or intermediate nuisance endpoint can look different from the publication endpoint if the starting model carried a stale kinematic `WGHT`; use the `.res/.hkl/.lst` paths printed in `QUICK_STATS.md`.

If a SHELXL feedback run stops near a later model update with `invalid_structure_model`, missing statistics, or an empty `dyn_nuisance_corrected.res`, the real problem is an invalid endpoint from the preceding cycle. Current GROND requires a non-empty, parseable electron-SFAC model with atom records, complete R1/wR2/N statistics, no NPD pathology, and a RES path/hash that still matches the summary-selected lambda. This also prevents an old endpoint directory in a resumed output tree from being paired with current metrics. GROND records `endpoint_res_health` and the rejected status in `shelxl_feedback_loop_summary.json` and keeps the previous clean model when possible. Inspect the failing cycle's `run.log`, `shelxl_iter_*.log`, `.lst`, `.res`, and `.ins` files to diagnose why SHELXL did not write a reusable endpoint.

If a SHELXL `.lst` reports `NON POSITIVE DEFINITE` or `atoms NPD`, GROND treats that as an ADP pathology, not as a clean model update. When an otherwise complete corrected-HKL step is NPD, GROND repeats the same step from its unchanged input model with a bounded `DAMP 100`, `300`, `1000`, `3000`, and `10000` ladder and accepts the first complete zero-NPD result. The undamped result and every retry retain matching RES/LST/FCF artifacts under `shelxl_attempt_iter_*`, while `npd_recovery` records the accepted value or an exhausted ladder. DAMP changes only the least-squares step size: GROND does not enable XNPD, add RIGU or other restraints, change the corrected reflections, or relax the zero-NPD gate. If every bounded step remains unsafe, or if a later pass fails, GROND restores an earlier matching clean RES/LST/FCF set when available and otherwise rejects the update. Split-atom warnings are reported separately but do not block endpoint selection by themselves. The relevant fields are `npd_count`, `npd_atoms`, `split_count`, `safe_for_feedback`, and `npd_recovery`.

If `GROND doctor --probe-bloch` does not include a top-level `grond` block, or if `grond.install_status` is `stale_or_incomplete_install`, the installed package is stale even if the command itself runs. This is the expected diagnosis when `required_features.shelxl_feedback_res_guard`, `usable_feedback_model_selection`, or `final_feedback_row_recompute` is false. Remove the old bundle or environment and reinstall from current GitHub rather than installing over it.

The feedback loop also writes a final `final_row_recompute_*` run after the last SHELXL update. This stage runs Bloch again on the final coordinates without performing another SHELXL update. The row statistics in `QUICK_STATS.md` should therefore correspond to the final structure, while the final endpoint `.res/.hkl/.lst` paths remain listed separately.

If an output `.res` still displays `L.S. 10`, `LS 10`, or `CGLS 10`, check which GROND build produced it. Current GROND normalizes generated endpoint `.ins` files to one internal SHELXL cycle before every corrected-HKL endpoint call. The command-line option `--shelxl-iterations` controls the number of external SHELXL calls, not the cycle count left inside the source model.

If the `post_bloch_sigma.status` is `ok_clipped`, the current model residuals wanted a sigma multiplier outside the configured guardrails. That is a diagnostic warning, not a polished result. Inspect the all-row `R1all`, residual trends, transform choice, resolution limit, and maps before treating the weighted statistics as publication-ready.

If adding crystals makes the combined raw-row statistics worse, inspect `dataset_policy/final/REPORT.md`. GROND should keep the strongest crystals as `primary`, keep useful but noisier crystals as `downweight`, and move weak nonredundant crystals to `completeness_only` so they can help endpoint coverage without steering the shared raw-row regularization.

If an optional Sg-jitter trial requests a profile point with no local excitation-error crossing, current GROND rejects that nuisance candidate and records it in `rejected_prediction_candidates.json`; it does not widen the two-degree local root bracket. Feasible candidates in the same gate remain available. If every requested candidate is infeasible, inspect `prediction_grid_failure.json` and correct the geometry or the requested jitter grid rather than increasing the root-search range.

If a continuous-thickness stage reports a rejected optimizer point or an error involving `thickness_grad_frac`, keep the physical gradient interval at `0` through `1`. Values above one imply a non-positive edge of the uniform thickness distribution and are outside the Bloch model's domain. Current GROND bounds every optimizer to the same local fractional basin around the coarse-grid thickness winner and independently rejects nonfinite, nonpositive-thickness, or out-of-domain results before promotion. There is no fixed physical 40--260 nm interval: a finite positive winner outside that range remains valid, and explicit thickness bounds must include the winner. Inspect the stage `summary.json` for the selected strategy, resolved local bounds, and rejected-candidate reasons rather than widening `--grad-max` or the local bracket to reach a remote oscillatory alias.

If a multi-crystal corrected-HKL endpoint is worse than the best single crystal or an XSCALE-style kinematic baseline, inspect `runs/combined/combined_summary.json` and confirm that `interdataset_scale.mode` is `overlap`. Large scale factors are a warning that the raw integrations were on very different arbitrary scales, but this is exactly why GROND now normalizes corrected reflections after the dynamical correction and before endpoint merging.

If a full run is slow, use `--fast` first, then inspect `logs/commands.jsonl` to see which stage dominates. The final high-basis prediction is usually the expensive step.

If a branch gives a suspiciously good strong-reflection R factor but poor all-row statistics, inspect the forensic reports before adding more beams. Weak-row, resolution, background, scale, and geometry trends often explain the gap better than a larger blind grid.
