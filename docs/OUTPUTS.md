# Outputs

`run_config.json` records command-line options, package choices, worker count, and dependency probe results.

`run_prep.json` records the exact input structure and reflection files used for the run.

`logs/commands.jsonl` is the timing ledger. Each engine stage has a start record and a completion record with elapsed seconds and return code.

`FINAL_SUMMARY.md` is the first file to open after `GROND auto`. It is intentionally short: final hand and hand Z score, selected HKL transform, input-model row statistics, final row-level statistics, the promoted corrected-HKL endpoint statistics, and the exact files to open next.

At the terminal, a successful `GROND auto` ends with `GROND finished successfully`, total completed stage time, final hand and Z-style support, input-versus-final row statistics, the promoted endpoint R values/GooF, and the first paths to open. The progress denominator shown during the run is an early estimate because optional gates may be skipped after decisions are made; if the final panel says the run finished successfully and names `FINAL_SUMMARY.md`, the workflow completed. Use `--json` when a script needs the compact machine-readable stdout payload.

`QUICK_STATS.md` is the compact audit report behind `FINAL_SUMMARY.md`. It gives the selected HKL transform, initial and final absolute-structure hand, final hand Z-style row contrast, free-row intensity residual RMSZ, final nuisance contract, the exact final LS1 feedback endpoint `.res/.hkl/.lst` paths, the exact publication endpoint `.res/.ins/.hkl/.lst` paths, stage timings, and the short requested-resolution, suggested-resolution, and endpoint-calibration tables without the full audit trail. Positive hand Z values in this file are oriented to favor the final selected hand, even when the underlying diagnostic JSON was written before a post-feedback hand promotion.

Different integration packages can give different signed-row contracts from the same frames. XDS and DIALS may differ in row filtering, Lorentz/partiality handling, scan-varying geometry, sigma estimates, scale conventions, and the exact set of integrated observations. GROND can still find the same transform and hand and give similar raw-row R factors, while nuisance fits such as thickness, frame offset, absorption fraction, and scale counts differ. Treat those nuisance values as fitted row-contract parameters unless the row contracts agree closely.

`grond_progress.json` stores completed stages for resume. Re-run the same command with the same output directory to continue after an interruption. A stage is reused only when its saved command matches the current command, so changing GROND installs, input paths, transforms, or material options forces the affected stage to recompute instead of mixing old and new outputs.

`grond_continue_checkpoint.json` is written by completed `auto` runs. It is the deliberate-continuation entry point: edit a model, then run `GROND push-endpoint --checkpoint grond_continue_checkpoint.json --start-res edited.res --out-dir endpoint_push_edited`. For one dataset, the checkpoint reuses the selected pinned row/nuisance summary. For multiple datasets, it records every accepted dataset's final row contract, pinned nuisance values, dataset-policy weights, and corrected-HKL merge key, then `push-endpoint` reruns the shared loop as per-dataset Bloch rows, one GROND-side corrected-HKL merge, and one shared SHELXL LS step per macrocycle. This skips scouting, hand testing, thickness search, and feature gates. It is not crash recovery; interrupted runs use `grond_progress.json`.

`finish_manifest.json` is written by `GROND finish --run-dir grond_out`. The `finish` command does not rerun refinement. It reloads `grond_summary.json` and `run_prep.json`, regenerates `FINAL_SUMMARY.md` and `QUICK_STATS.md`, and by default writes native row-level dynamical Fourier maps in `native_dynamic_maps/`.

`GROND finish` and `GROND publish` also print the same human terminal summary by default. Add `--json` if an automation expects the old compact JSON payload on stdout.

The native map package contains `native_dynamical_coefficients.csv`, `native_dynamical_coefficients.hkl`, `grond_native_dynamical.cif`, `grond_native_dynamic_fo.map`, `grond_native_dynamic_2fofc.map`, and `grond_native_dynamic_fofc.map`. The observed electron amplitude in these coefficients is not read from a SHELXL FCF file. It is inferred from the selected native row table as `|F_dyn_obs,row| = |F_model| sqrt(I_obs / I_dyn_scaled)`, merged by signed HKL, and phased with the selected model phase. For multi-dataset runs, `finish` uses the selected combined-endpoint input row tables and records every contributing row table in the manifest and CIF. The Fo-Fc map uses `[|F_dyn_obs| - |F_model|] exp(i phi_model)`, and the 2Fo-Fc map uses `[2|F_dyn_obs| - |F_model|] exp(i phi_model)`.

For a quick endpoint-map diagnostic, run `GROND finish --run-dir grond_out --map-mode shelx2map`. That mode uses `shelx2map` and the selected corrected-HKL endpoint `.fcf`, and writes `grond_corrected_fo.map`, `grond_corrected_2fofc.map`, and `grond_corrected_fofc.map`. Those maps are fast endpoint checks, not the native row-level dynamical map package.

`runs/<dataset>/.../native_dyn_calc.csv` is the row-level table with observed intensity, uncertainty, predicted dynamic intensity, predicted Born intensity, scale, raw-row resolution-envelope factor, and nuisance information.

`summary.json` files hold machine-readable statistics. `REPORT.md` files hold the same information in a human-readable form.

Endpoint `summary.json` records include `iteration_history` for SHELXL polishing. Each entry includes the endpoint `R1gt`, `R1all`, `wR2all`, `GooF`, the active `WGHT`, the recommended `WGHT`, and the declared weight mode. Production corrected-HKL endpoints default to fixed `WGHT 0 0` after GROND sigma calibration, while inherited or promoted SHELXL empirical weights are diagnostics. The final endpoint should be judged from the last iteration and the `.lst` path named in `QUICK_STATS.md`, not from an intermediate nuisance `.res`.

Corrected-HKL endpoint manifests also include a `post_bloch_sigma` block when endpoint sigma calibration is active. The default final-policy block is `uniform_z_rms`: GROND fits one current-model intensity scale, computes the RMS of `(Iobs - K Fc^2)/sigma`, scales all endpoint sigmas by that single scalar, and reports train, held-out, and all-reflection RMS(z) diagnostics. This is needed because the sigmas that enter GROND belong to the measured integration table, while the final corrected HKL has passed through Bloch regularization, row scales, nuisance corrections, and merging. Leaving those sigmas unchanged can make weighted statistics report the old integration uncertainty instead of the uncertainty of the transformed endpoint. The block is an endpoint uncertainty statement, not a new integration-noise claim and not a physics-selection criterion. `R1gt` and `R1all` remain the least weight-sensitive endpoint checks; `wR2all` and `GooF` should be read together with the declared `post_bloch_sigma.policy`, `sigma_scale`, and residual diagnostics.

Corrected-HKL endpoint directories contain `dyn_nuisance_corrected.hkl`, the unmerged companion HKL, `.ins/.res/.lst/.fcf` files from the endpoint polish, and maps when the external map tool is available. Endpoint `.res` files are normalized for reopening: the active block uses one LS/CGLS cycle, the `HklSrc` points to the corrected HKL, the declared active `WGHT` is in the pre-`END` block, `ACTA` is stripped, `HKLF` is forced to `HKLF 4`, and SHELXL's ignored post-`END` recommendation tail is stripped. Full auto keeps EXTI off for promoted outputs. Any explicit EXTI run is a diagnostic comparison rather than the final physical path. `HKLF 5`, `TWIN`, `BASF`, `SWAT`, and SQUEEZE/solvent-mask corrected endpoints are current limitations and are rejected by preflight.

`forensics/<dataset>/` contains residual, pre-merge, dose, observation-correction, and endpoint-promotion audits when those gates are enabled.

`scale_polish/<dataset>/` contains the adaptive frame-scale compression audit. It writes `scale_compression_candidates.csv`, `scale_compression_summary.json`, a readable `REPORT.md`, and `selected_compact_run/native_dyn_calc.csv` when a compressed model passes the all-row gates. The default audit keeps the detector-position scale grid exact, compresses only the frame-scale manifold, and gates on all-row R factors rather than strong-row-only improvements. Candidate rows include the native row-space chi-square, GooF, and AIC/BIC-style information criteria. These are interpreted only after the residual gates pass, so a very coarse model is not promoted merely because it uses fewer scales. The in-regularization `--scale-smoothness` penalty is experimental and defaults to zero because it can suppress real frame-scale structure; the publication parameter reduction comes from this post-hoc accepted compression table. For a deeper check, `GROND scale-replay` can replay named scale contracts such as `baseline`, `adaptive:293:det8`, or `window:3.0:det8` through corrected-HKL endpoints and report both promoted-`WGHT` and fixed `WGHT 0 0` outcomes.

`endpoint_calibration/` is the recommended final publication replay when a frozen row table already exists. In `GROND auto` it is run after the final row-level table has been written, and the same replay can be run directly with `GROND calibrate-endpoint`. The command writes `scale_contract_endpoint_replay.csv`, `summary.json`, and `REPORT.md`. The report names a low-R diagnostic endpoint separately from the selected publication endpoint. The publication endpoint is chosen from fixed `q`, fixed scale contracts, calibrated endpoint sigmas, and by default a fixed `WGHT 0 0` SHELXL branch. The default scale-count rule is `--publication-selection-policy bic`: candidates must be finite, use the preferred weight mode, and pass the configured GooF window, then GROND picks the branch with the lowest `bic_fitted_variance`. R1all cost and held-out row wR2 cost are reported as diagnostics instead of private promotion gates. If no candidate passes the hard sanity gates, the report still names the least-bad fallback and lists every failed gate so the result is not silently promoted. The old smallest-passing-scale-count behavior is available as `--publication-selection-policy gated-smallest` for reproducing older audits.

`dataset_policy/structure_update/` and `dataset_policy/final/` are written for multi-dataset jobs. The policy table classifies each crystal as `primary`, `downweight`, `completeness_only`, or `exclude`. Primary datasets keep full raw-row weight. Downweighted datasets stay in raw-row regularization, but their effective sigmas are inflated so they cannot dominate gradients. Completeness-only datasets are excluded from raw-row structure statistics and shared-model feedback, but their endpoint rows can still improve merged coverage. The final policy directory also contains `weighted_runs/<dataset>/native_dyn_calc.csv`; combined endpoint export can consume all non-excluded weighted runs, while GROND row/MR publication row metrics use the primary and downweighted subset. The combined endpoint summary records `interdataset_scale`, an overlap-derived per-crystal scale applied after dynamical correction and before merging. By default, overlap scaling and endpoint HKLF4 export use `model_symmetry`: symmetry-equivalent corrected observations are inverse-variance merged before the shared SHELXL LS step, while Friedel opposites stay separate in acentric space groups. The diagnostic `model_symmetry_friedel` mode also merges Friedel mates, and `exact_signed_hkl` reproduces the older signed-row-only endpoint merge. The summary also records the active per-dataset sigma policy, endpoint merge key, merge-sigma policy, post-merge endpoint sigma policy, endpoint `WGHT` policy, and endpoint LS/CGLS cycle count. In the default multi-dataset `auto` path, each crystal is calibrated independently before merging, then merged reflections that disagree beyond formal propagated sigmas are assigned larger uncertainties through `chisq_overdispersion`, then the merged endpoint is replayed with `WGHT 0 0`. This lets marginal crystals add real completeness without letting optimistic sigmas or stale kinematic SHELXL weights steer the final endpoint. The production shared-model update is the combined LS1 feedback path: GROND recomputes each dataset's Bloch rows from one shared model, merges corrected rows, runs one shared SHELXL update, and repeats. The native finite-difference multi-dataset updater remains available with `--structure-update native_gradient` for diagnostic checks.

`resolution_limits/<dataset>/` contains the promoted resolution-limit audit for one final row table. It writes `resolution_shells.csv`, `summary.json`, and `REPORT.md`. The shell table reports signal, split-half stability across symmetry-equivalent row groups, dynamic and Born GROND row/MR `Rall`/`wRall`/`MRall`/`MwRall`, cumulative metrics, and work/free stability when the final row table has enough held-out rows. A shell is promoted only when it stays inside the configured signal, stability, and GROND row/MR residual gates. Multi-dataset `auto` runs also write `resolution_limits/combined/` so the final merged endpoint has the same audit as the individual crystals.

`endpoint_chooser/` contains the publication endpoint chooser. It writes `publication_endpoint_choice.json`, `PUBLICATION_ENDPOINT_CHOOSER.md`, and `publication_endpoint_chooser.tex`. This report separates the best physical endpoint from the best single-dataset physical diagnostic and the best rejected diagnostic endpoint, then lists why each rejected correction was not promoted. In a multi-dataset run, a lower-residual single-crystal endpoint is not allowed to replace the combined endpoint in the publication slot. Physical endpoints must keep EXTI off, keep endpoint-B at zero, have finite endpoint statistics, pass HKL safety and modulation gates, and pass the raw-row/endpoint holdout gates if they come from the optional observation-polish path.

`tables/` contains the run-level publication table artifacts. `publication_table.md`, `publication_table.tex`, and, when a LaTeX engine is available, `publication_table.pdf` report GROND row/MR `Robs`, `Rall`, `wRall`, `MRobs`, `MRall`, and `MwRall` for the final dynamical row model and the matched Born/kinematical model. The unmerged R factors are calculated directly from `native_dyn_calc.csv`; the MR factors are calculated after arithmetic merging of model-symmetry-related rows with propagated merged uncertainties. Auto reports three endpoint rows so the decision is auditable: the requested resolution with the full fitted scale curve, the requested resolution with accepted compact scale parameters, and the final suggested endpoint using the promoted resolution limit with the suggested compact scale model. When the default compact scale-manifold pass runs, the same table also reports full-to-compact scale and total parameter counts plus all-row residual penalties and information-criterion diagnostics, so the nuisance-parameter savings are visible in the final report outputs. Endpoint `wR2all` and GooF are reported with the declared post-Bloch sigma policy and SHELXL `WGHT` policy; they should not be compared across different weighting policies without that context. The machine-readable values are also written to `row_mr_metrics.json`.

Small examples of the input and output file structures are in [FILE_FORMATS.md](FILE_FORMATS.md). Start there if you want to know what a reflection JSON line, row-level CSV, corrected HKL, summary JSON, or resume file looks like before opening a real run.
