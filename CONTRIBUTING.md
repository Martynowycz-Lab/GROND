# Contributing

GROND welcomes contributions that keep the project open, auditable, and clean-source.

All contributed code must be your own work or derived from sources that can legally be used in an MIT-licensed open-source project. Public scientific papers, public documentation, public repositories with compatible licenses, and public file-format examples are acceptable foundations when cited appropriately. Proprietary source code, confidential documentation, decrypted modules, reverse-engineered private internals, vendor-only implementation details, or code copied from incompatible licenses are not acceptable.

If a contribution is based on a publication, public repository, public example dataset, or public documentation, mention that source in the pull request and add a citation or short comment where it helps future readers. If you are uncertain whether a source is public or license-compatible, do not include the code until the provenance is clear.

Contributors should preserve GROND's scientific audit trail. New workflow features should write enough logs, JSON summaries, CSV tables, or report text for a user to understand what was tried, what was promoted, what was rejected, and why. Features that improve one residual while degrading maps, chemistry, held-out statistics, or parameter discipline should be reported as diagnostic unless there is a clear physical reason to promote them.

By contributing, you agree that your contribution can be distributed under the MIT License.
